# 安装与一次性诊断

这是可执行插件，不需要在求职会话中审计源码或重新开发。

正常安装：解压根目录，执行 `node scripts/install.mjs`，完全重开 Codex，安装 / 启用“Coming Jobs”，按宿主提示审阅并信任 hooks。再开新会话。

安装器固定使用它找到的 Node 绝对路径、当前版本的不可变代码目录，以及独立 `JOBOS_NEXT_HOME`。正常运行无需猜 cwd、模型或工具名。

## 插件工具不可用时

只做一次检查：当前是否能发现 `jobos_next` 下的 `jobos1_context`。能调用时以返回的 `contract=jobos/1`、version、build、workspace_id 为准。不使用旧 `mcp__jobos__` 工具来替代。

如果不能调用，读取安装结果文件（路径由安装器返回），检查 state 与当前启用项。可以从**当前明确安装目录**运行：

```sh
node --no-warnings src/cli.mjs context
```

这是本地只读诊断，不是启动另一套旧服务。不要遍历全部缓存找“也许能工作的”接口；不要扫描整份 Memory、所有知识库和数据库。如果缺少对应安装目录，就让用户运行解压包里的安装器一次，不能猜私人路径。

`cli_install_completed` 不代表这个既有会话的工具已刷新。新会话验证是必要的。不要把官方插件来源就绪和真正启用混为一谈。

## Hooks

SessionStart / UserPromptSubmit 给本轮简短工作规则和会话标识；PostToolUse 只标记本插件活跃；Stop 检查有没有保存交接并给一个下一步。

Stop 最多要求一次收尾修正，尊重 `stop_hook_active` 与用户暂停。脚本不读取完整会话文件，不联网，不操作浏览器，不批准安装或传输、不写宿主的权限信任。

只有 Codex 受支持并经用户原生信任的 hooks 才会执行。不能通过手动改安全设置绕过信任流程。

## 卸载与恢复

在 Codex 停用或卸载 `coming-jobs` 即可，不自动删除 `~/.jobos-next`。如要重新使用旧版，请先停用新版，再在原生界面启用旧插件；安装备份目录保留配置原文。不要在配置后来已有新改动时无脑整份回滚覆盖。
