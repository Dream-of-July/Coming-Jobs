beta.14 源码新增全表资料匹配、已知选填字段、公司别名、多志愿名额与顺序、简历改写依据、已审核材料复用、表单联动回读和短时验证码回归用例。原有测试覆盖申请状态、内容授权、完整岗位范围、每日预算、上传阶段门槛和私有工作区迁移。这些都是合成测试，不向雇主发送投递。

完整测试需要启动本地 Node 子进程，并在回环地址运行合成 HTTP 服务。沙箱禁止这些操作时可能产生环境错误，需要与断言失败区分。合并运行时可使用 `--test-isolation=none` 查看逐项结果。

## beta.14 源码验证

2026-10-22，在 Linux、Node.js 24.19.0 环境中完成合并后的整套回归：**443 项通过、0 失败、0 跳过**。发布文件完整性、公开仓库模式检查和 Skill 格式校验也已通过。安装器测试使用临时目录并检查新 MCP 进程，不代表已有 Desktop 会话已更新。

新的八字段标签控件用例执行九次 DOM 读取：八次写前读取，以及一次最终批量读取；此前同一路径为十六次。最终读取也会检测后续字段清空此前字段的情况。这个对照只统计局部调用次数，不表示实际耗时或整次投递提速。

验证码测试使用内存宿主适配器、受控时钟和虚构消息，覆盖立即读取、有界轮询、过期和不匹配消息、能力缺失、人机验证交接，以及不含秘密的结果。未使用真实账号或验证码。真实宿主适配器仍需验证消息与请求的关系，并设置自身读取超时。

简历测试覆盖改写、基线遗漏、完整数字匹配、公司范围证据、PDF 字节绑定的提取文本，以及不改写源文件审核的复用。编辑警告不等于语义证明，详见[流程接入与限制](WORKFLOW-RELIABILITY.md)。

## 当前宿主证据及边界

更名前的 beta.8 在真实 Codex Desktop CUA 中完成过本地八字段普通表单测试，写前 checkpoint、逐字段写入/回读和插件回执均通过。测试发现过定位器读取超时，之后切换到宿主支持的只读控件查询。

| 稳定合成路径 | CUA 往返 | 整页读取 | 字段一致 |
| --- | ---: | ---: | ---: |
| 逐字段填写及整页回读 | 9 | 9 | 8 / 8 |
| 有限批次及字段回读 | 3 | 2 | 8 / 8 |

这是普通字段的局部对照，排除开发排查、插件调用和初始化；统计模型与 CUA 往返，不是底层浏览器请求或总 Token。附件前置条件为 fixture，不代表已在该次测试中完成真实上传，也不能推广为整次投递提速比例。

更名后的 beta.9 独立检查回归、安装、完整性和新 MCP 进程，不把 beta.8 的宿主证据说成一次新的 beta.9 真实投递。

## 已知限制

- 目前仅为 Codex Desktop 优化，macOS 是参考环境。
- 学校候选项、日期联动、简历解析和照片需要逐门户观察；文件名或 98% 进度不能证明附件已关联。
- 完整性只能检查已批准清单，不能编造缺失经历，也不能独立证明宿主提交的 PDF 提取文本。
- 经验验证和时间指标依赖宿主提供真实证据，不能把成功提交当作岗位匹配准确。
- 保存调度配置后，仍须成功绑定宿主才能称为已运行。
- 文档中英双语，部分运行时界面和校验文案仍为中文。
- 后续观察 3–5 次真实投递，再评价实际效率收益。

优先用合成页面和虚构候选值，提供插件构建、Codex Desktop 版本、预期、实际结果，以及是否保护了用户修改。不要上传真实简历、令牌、测评专属链接、完整聊天或含个人资料的截图。
